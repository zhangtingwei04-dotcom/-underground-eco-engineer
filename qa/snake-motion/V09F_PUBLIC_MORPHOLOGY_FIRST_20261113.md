# 歐姆透明蛇 V0.9F｜外形先行、再做 24 節來源動態驗證

- 日期：2026-11-13（Asia/Taipei；此研究始於 11/12 晚間）
- 儲存庫：公共 neutral synthetic QA `zhangtingwei04-dotcom/-underground-eco-engineer`
- **GitHub Actions 最終驗收**：[Public OHM Snake and Terrarium QA #43260480065](https://github.com/zhangtingwei04-dotcom/-underground-eco-engineer/actions/runs/43260480065)，**8/8 工作成功**；包含原有蛇／生態箱回歸、V0.9F 靜態 Chrome 雙橫式與 V0.9F 新動態 Chrome 雙橫式。這是 source／工程視覺 QA，**不是正式遊戲、美術自然度或生物學比例驗收**。

## 一、使用者批准的順序

1. **先修透明外形**：頭型、細頸、軀幹、體長粗細、背腹厚度、尾部漸細；骨架未改。
2. **靜態檢查**：至少直線、S 型、轉向的 24 節來源姿態；Chrome 1440×900 和 932×480 真實渲染逐張檢查。
3. **通過靜態後才做動態**：原本 24 節 V0.9C source frame，沿用 V0.9D 自我接觸安全停止；不同動作影格的透明外形不得突然換比例。
4. **後續各物種沿用流程，不沿用固定的蛇身比例**：不同的蛇與其他動物，其頭型、尾長、軀幹、四肢、骨架數與接觸方式均依物種科學參照及原創設定獨立開發；不以 24 節蛇體套所有動物。
5. 動態自我碰撞與真正接觸力合格之前，**不畫正式蛇皮，不修改私人遊戲或玩家存檔**。

## 二、實際新增及修改

- `src/ohm-core/snake-transparent-morphology-v09f.mjs`（新）：中立 `generic_snake` 外形候選，沿原 24 節、總長 2.28 source units 的骨架，建立 **139 段身體半徑剖面、9 個頭部橢圓剖面**。採用受控 cubic interpolation 保持曲線平滑，**每一個 source joint 在對應索引處完全不變**。
- 外形特色：收細頸部、主軀幹較纖細、頭部前後寬度有自然變化、吻端逐步收細，後段尾部由主軀幹逐漸減小。中立合成相對半徑值：約頸 `0.053`、主軀幹 `0.071`、頭部最寬 `0.083`、尾尖 `0.007`。**這些數字只屬本專案的工程美術比例，不是玉米蛇／豬鼻蛇的科學測量結果，也不是正式歐姆物種規格。**
- 透明 mesh 模型與 front-glass 2.5D 畫面取自同一組 render candidate rings；保持無外皮、無花紋、無正式眼部素材。這個**新 visual mesh 沒有取代原 V0.7S 身體、頭部和場景碰撞權威**；未完成新網格的持續掃掠碰撞及動物肌肉物理。
- `tests/snake-transparent-morphology-v09f.test.mjs`：直線／較明顯 S 型／轉向靜態姿態、來源關節不變、頭頸區分、逐段收細、可重播性、V0.9D 原先 190 組自我接觸來源檢查仍存在。
- `snake-morphology-v09f-lab.html`：三種姿態的透明靜態 QA，可在網頁、手機橫式顯示；**不是正式展示圖**。
- `tests/snake-morphology-v09f-cdp-browser-qa.mjs`：真正 Chrome 1440×900、932×480 兩張 PNG 和同一 canonical canvas 來源 digest；已取得工程畫面，經人眼檢查確實比前版更纖細。
- `tests/snake-transparent-morphology-v09f-motion.test.mjs`：靜態之後的 24 節動態變形測試。從真實 V0.9C 來源的 **60→530 source frames** 逐步運行，分別量測 **8 個關鍵影格（60、61、120、160、240、410、500、530）** 的新透明形態；保持骨架、頭部連接、比例和存檔不變，且在第 531 幀仍應被原 V0.9D 嚴格自撞警告停止。
- `snake-autonomy-v09d-lab.html?morph=1`：顯示來源 V0.9C 姿態上的**新 V0.9F 透明外形**，只允許播放至 530 幀安全候選。其原始 V0.9D 顯示與 `?unsafe=1` 原有診斷路徑仍保留。
- `tests/snake-morphology-v09f-motion-cdp-browser-qa.mjs`：新外形真實 Chrome 動態影格 60、160、410、530（兩個橫式尺寸，各 4 張），以及在要求 692 幀時會被阻止的雙視窗安全畫面（再 2 張）。Chrome 測試確認每次畫面來自 24 節骨架、完全沒有畫皮和已知的不安全後期來源影格，**沒有誤稱已獲得新的網格碰撞憑證**。

## 三、真正的視覺檢查結論

已檢視 **V0.9F 真實靜態 Chrome 寬橫式 + 手機橫式**，及**來源動態**關鍵畫面：

- 靜態：比 V0.9F 第一輪過厚軀幹更細，尾尖不再突然截斷；頭部仍屬中立簡化設計，缺乏正式物種辨識特徵，不能直接宣稱最終蛇頭已完成。
- 動態去程：新透明形體能跟著真正 24 節來源骨架轉動，且不會每個路點重建一條新蛇。
- **動態折返仍不夠自然**：第 530 幀可見蛇盤成過緊的小圈，原 V0.9D 會在第 531 幀前停止；需要讓尋路考慮**尾部所占空間、可用轉彎半徑與支撐接觸**。不能把「仍然安全停止」解讀成「動態自然完成」。
- 工程截圖中透明蛇只是小型動物測試模型，不具備正式美術、環境遮蔽及像素材質品質；UI／視角也不是未來正式遊戲的設計。

## 四、具體未完成事項

- 新頭部／軀幹 render candidate 的 **3D mesh vs scene/terrarium** 連續、掃掠、自我接觸碰撞審核未完成。原 V0.7S source 骨架的安全驗收與新 visual mesh 碰撞是**兩種不同**驗證，不能混淆。
- 頭頸連接的生物學外形、眼眶／吻部／下顎分層、腹側曲線仍待物種專屬設計與人工觀感審核（不代表現在就要加鱗片或眼睛）。
- V0.9C/V0.9D 折返路線仍會靠得太近；V0.9E 已有上下接觸分類，但**尚無真正抬身／反力/摩擦求解器**。本輪只修外觀與其跟隨動態，**未假稱修正了完整自身交疊**。
- 尚需多種環境形狀、長時間移動、不同裝置實機 Safari FPS 與視覺審查，再決定是否可以有限度合併到私人正式遊戲。
- 公共 QA 完全 neutral；沒有加入任何私人原創物種、NPC、故事、玩家資料、真實研究素材、第三方漫畫／遊戲資產。

## 五、下階段行動

採用本次外形改善做**候選比例基準**，先攻克「尾部占用+全身回轉空間的安全自主路線」和「頭部與新透明外形 mesh 接觸」；達到自然長時間動態與跨裝置觀感後才進入正式蛇皮像素化。其他物種遵守**生態／解剖證據→骨架→透明外形→靜態 QA→動態/接觸 QA→原創外皮**的先後順序，但保持獨立的身體資料契約及物種特徵。
