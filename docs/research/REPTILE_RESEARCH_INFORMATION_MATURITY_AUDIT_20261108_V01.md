## 三、可立即作為內容原型的部分（不是完整數值系統）

1. 新手可理解的**物種認識**、原生棲地 vs 圈養環境區分，以及圖鑑引用來源。
2. 在適當棲地中提供**可挖掘底材、躲藏處、探索空間、攀爬環境等選擇機會**；對應兩種蛇需遵守特定物種證據。
3. 玉米蛇**進食後可能出現選溫及代謝狀態變化**；描述狀態即可，不寫死「72小時一定消化完」。
4. 蛇的**躲藏、探索、吐舌、防禦**可以分類記錄；不直接以單一行為推論情緒、疾病或玩家羈絆。
5. 現實資料與歐姆虛構設定、專業論文與飼主經驗可清楚分層呈現。

## 四、尚未達到「完整飼養模擬」的主要條件

- 每種蛇按**不同生命階段、空氣／表面溫度、濕度、底材、通風、躲藏、尺寸、餵食與蛻皮狀態**分別核對照護條件，尤其是精確且有爭議的數值。
- 更長期、跨季節、可解釋的行為日誌與**轉換條件**；沒有可靠定量資料時以證據標記的保守規則代替捏造百分比。
- 釐清**自發正常行為與動物福利警訊**；醫療僅提供求助獸醫的合理提示，不把研究疾病盛行率轉成日常危險機率。
- **原始資料保全**：整理取得授權的來源、每個原始檔實際存放位置、checksum、版本、可讀性及資料取得狀態；D1 只有索引不能當檔案備份。
- 在研究資料可信之後再開發低負擔的**生態行為原型**；手機／電腦效能與玩家體驗分別測試。

## 五、下一批工作建議（P0 優先）

1. **西部豬鼻蛇飼養條件與長期觀察證據**：官方／特寵獸醫與飼主指南交叉核對；不照抄一般玉米蛇要求。
2. **兩種蛇的「照護知識條目」表**：逐條標 `A/B/C/D`、用途、是否可作新手教學、是否需獸醫確認。
3. **行為分類的最小可行集合**：`rest`, `explore`, `hide`, `burrow` 或 `climb`, `forage`, `post_feed`；只先設定有條件可觸發的行為，**不填無來源的精確機率**。
4. **原始 CSV 與研究 PDF 的保全計畫**：列實際擁有／只可查 URL／沒有原檔；避免研究成果誤認為已備份。
5. 先用**一個安全、新手可理解的豬鼻蛇與玉米蛇飼養示範**檢驗資訊能否讓玩家學到正確的環境選擇；完成驗證後擴充物種。

## 六、研究優先順序

**P0 初始兩種蛇 → P1 其他爬蟲 → P2 直接支援爬蟲的底材與微型生態 → P3 一般植物、菌類、礦物與地質 → P4 歐姆特殊地下生態。**  
若 P2 資料是完成 P0 飼養教學的必要條件，可提前少量收集，但不改變爬蟲首要的整體方向。

## 七、稽核限制

- 本次檢查 GitHub 的兩個 `src/ohm-core` 模組，不是所有遊戲場景、系統、測試及圖形資產的完整程式碼稽核；因此**不能**據此判定全部現有遊戲機制／可玩完成度。
- Cloudflare D1 統計反映查詢時的索引內容，不代表逐一驗證32篇論文全文，亦不等於完整研究成果已在雲端備份。
- 稽核沒有變更雲端資料結構、遊戲主程式、存檔系統或第三方原始資料。
