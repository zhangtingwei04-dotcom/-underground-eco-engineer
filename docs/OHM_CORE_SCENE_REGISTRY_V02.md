# Ohm Core v0.2：世界與場景管理（2026-11-08）

## 開發目標
先建立獨立、可執行的場景圖與導覽資料基礎，未來用相同核心規則支援 Phaser 網頁版、手機／桌面版與自有 Ohm 渲染器。本次不改正式玩家存檔，也不替換任何現有場景畫面。

## 本次實作
- `src/ohm-core/scene-registry.mjs`：新增獨立的場景資料與驗證器 `validateSceneRegistry`。
- `describeScene(world, registry)`：將目前所在場景、名稱、簡介與可前往地點輸出為 UI 可直接使用的資料，不依賴 Phaser。
- `travelToScene(world, location, registry)`：檢查是否真的是相鄰出口，再呼叫既有 `dispatchWorld` 產生移動事件。
- `tests/scene-registry.test.mjs`：場景完整性、有效出口、移動保護、禁止跳躍非鄰接場景、輸入狀態不變等 11 項檢查。
- `ohm-core-test.html`：根據場景定義動態生成出口按鈕，測試場景切換、觀察、世界時間推進。
- `.github/workflows/ohm-core.yml`：納入新模組語法與單元測試指令。

## 場景資料初版
- 地下研究所（起點）：通往生態箱室、研究圖書館
- 生態箱室：通往地下研究所
- 研究圖書館：通往地下研究所

以上僅作為**核心引擎的示範地圖**，不是歐姆自治聯合國正式世界地圖定稿。往後以遊戲世界設定為準，逐步建立各地區、警戒所、商店與野外探索入口。新增地點時透過場景註冊表，避免每一頁畫面各自硬編碼出口。

## 正式架構原則
- 只允許場景圖定義的鄰接移動，不可隨便傳入任何場景 ID 就瞬間移動。
- UI 只需顯示 `describeScene` 提供的出口；當前位置與已探索狀態由世界核心管理。
- 核心與視覺呈現分離，未來可改用第一人稱 2D 圖片及畫面底部出口欄；資料層不需跟著改寫。
- 場景應支持後續擴充：營業時段、角色出現、任務條件、通行證及分區載入，但 v0.2 尚未實作這些動態規則。
- 暫不串接正式 SaveSystem，也不新增必做日常任務。

## 驗收狀態
原始碼與 GitHub Actions 自動測試設定已提交。需要確認 Actions 執行結果與實際 GitHub Pages 手機操作；**不可只因檔案提交成功就聲稱測試全部通過**。

## 下一步
1. 在隔離測試場景建立 Phaser adapter：由 UI 呼叫 Ohm Core 並訂閱事件。
2. 加入有限狀態的條件出口，例如指定通行證，並用純測試驗證不會被 UI 繞過。
3. 擴展正式區域時先驗證與既有世界設計是否一致，不提前自動建立正式遊戲地圖。
