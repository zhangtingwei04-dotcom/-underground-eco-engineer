# Ohm Core — 現實時間同步服務 v0.1（2026-11-08）

## 已確認需求
玩家進入正式遊戲場景時，讀取一次現實時間作為起點；遊戲持續開啟期間，以經過時間持續取得現實時間，場景無須自己累加虛擬時間。手機從背景回到前景時檢查是否需要校準。

## 已實作（初步）
- `src/ohm-platform/browser-game-clock.mjs` 提供 `BrowserGameClock`、`getBrowserGameClock()`、`startBrowserGameClock()`。
- `src/scenes/UndergroundScene.js` 在玩家進入地下研究所遊戲場景時啟動時鐘；不在登入畫面一開啟就開始計時。
- 初次啟動時，使用裝置 `Date.now()` 紀錄現實起點，結合 `performance.now()` 的單調經過時間推估現在時間；查詢為即時計算，不需要每秒觸發定時器。
- 回到前景／視窗取得焦點時，檢查裝置時鐘是否與推估時間相差超過 30 秒，必要時重新校準。
- `snapshot()` 輸出現實時段（早晨／下午／傍晚／夜間），透過 `browser-time-context.mjs` 使用台灣時區。
- `tests/browser-game-clock.test.mjs` 測試起點、時間推進、漂移、恢復與安全失敗路徑；GitHub Actions 配置已更新。

## 重要邊界
1. 這不是 Supabase 登入認證事件的時間紀錄，而是**首次進入遊戲場景**即初始化；目前正式登入／遊客流程仍需後續整合。
2. 只有共用時間服務取得時間，**不修改** `world.clock`、NPC 作息、商店營業、離線生態結算、存檔結構或經濟獎勵。
3. 手機切入背景時，不會持續每秒執行模擬；恢復時靠經過時間計算與時鐘重新校準，可節省電力。
4. 裝置時鐘可能被改動或偽造，不可把此時間當成具有權威性的伺服器時間。涉及公平性、獎勵、交易或排行榜的時間應由伺服器確認。
5. 若長期運行時系統時鐘有明顯漂移，至少要在場景進入或前景恢復時做 recheck；後續可根據需要加入低頻校準，不應每幀查詢網路。
6. 這只是時間服務基礎。沒有完整的 NPC 日夜排班運算或可靠伺服器校時。
7. 實際手機及 GitHub Actions 的結果尚待驗證，不能因提交原始碼就宣稱全數測試通過。

## 下一步
- NPC、商店營業與場景事件只讀取統一服務給定的時間快照，而非各自 `Date.now()`。
- 加入時間事件訂閱（時段轉換觸發），避免每個 NPC 每秒輪詢。
- 討論遊戲世界的時區政策：是否固定歐姆時區，或依遊戲地區世界規則。
- 最後才考慮可信伺服器時間與離線進展同步。

## 2026-11-08 補充決策：每日早、中、晚各偵測一次

使用者指定三個主要時段各偵測一次，不需要每名 NPC 或每個場景不斷輪詢時間。

- **初版時點（可配置）**：早上 06:00、中午 12:00、晚上 18:00（台灣時區）。這是排程預設值，非歐姆世界觀的正式時段定稿。
- 登入後進入遊戲場景，先初始化時間基準，已過去的當日檢查點不倒追觸發。
- 遊戲保持開啟時，只排程**下一個檢查點**，不每秒輪詢、不因移動場景額外增時。
- 裝置切回前景時重新校準並檢查；若休眠期間錯過多個檢查點，**只通知最近一個**，避免大量補發 NPC／商店事件。
- 同一天每個檢查點最多觸發一次（目前僅使用瀏覽器執行期間的記憶體去重，重啟後不追溯過往事件）。
- `src/ohm-core/daily-time-checkpoints.mjs`：純規則；`src/ohm-platform/daily-time-notifier.mjs`：瀏覽器排程與訂閱。
- `UndergroundScene` 已啟動通知服務；現階段**沒有訂閱 NPC／商店處理器，因此不會直接改變班表、營業狀態或保存遊戲資料**。
- 設計仍以裝置時間為展示及低風險日常互動來源，無法防止手動改時鐘；涉及交易與獎勵需伺服器時間。
- 已加入測試程式與 CI 設定，但手機與 GitHub Actions 結果尚待確認。
