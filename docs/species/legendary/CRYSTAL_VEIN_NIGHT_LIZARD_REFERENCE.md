## 一、已確認的開發用途

1. **傳說生物系統的第一個實驗物種**：日後用於測試個人世界／世界級事件混合制度（C）、條件判斷、研究門檻、稀有出現時間與防修改裝置日期。
2. **飼養箱系統的第一個開發測試寵物**：以隔離的測試資料驗證個體生成、紋路差異、飼養箱展示、觀察互動、基本需求欄位，以及個體 ID 的一致性。
3. **紋路系統的代表性測試個體**：用於驗證同物種有多種可辨認的個體紋理，而不必誇張改變解剖結構。

> 「第一隻飼養箱寵物」指**開發原型與測試順序**，不是對正式遊戲新手起始寵物的定案。正式遊戲初期仍優先展示真實爬蟲與生態教育；傳說生物預計在中後期開放。

## 二、概念形象（暫定）

- 地下岩縫／晶洞活動的蜥蜴形生物；整體保留可信的四肢、身體、尾巴與感官比例。
- 深色鱗片表面出現晶脈般細緻的紋路；青藍、冷白、藍綠色只是美術試色。
- 「晶脈」可以先從反光、色素或表皮微結構的視覺表現著手；**不能先斷言牠能生物發光**。
- 食性、溫濕度範圍、代謝、繁殖、社會性、捕食者、晶礦環境適應與保育地位均待查證與設計。
- 真實參考候選：守宮、石龍子及其他岩棲蜥蜴；不能把不同物種的習性混為一談。

## 三、紋路系統測試欄位（不是正式遺傳法則）

| 欄位 | 初期測試方向 | 注意 |
|---|---|---|
| patternSeed | 固定生成種子 | 同一個體再次載入應維持相同紋路 |
| primaryVeinPath | 背部／側面／尾部主紋路路徑 | 不超出身體 UV／遮罩 |
| branchDensity | 分枝密度 | 必須可控制效能與視覺清晰度 |
| veinThickness | 粗細 | 不因稀有度無限制膨脹 |
| symmetry | 左右對稱程度 | 可以不對稱，但須符合設定 |
| patternHue | 紋路偏色 | 和「真正發光」分離 |
| reflectivity | 反射視覺強度 | 只是呈現參數，不等於生物能力 |
| rarityTag | 稀有特徵註記 | 不直接等同捕捉或交易價值 |

### 個體紋路案例（測試代號）

- 主脈型：背部有連續的主要晶紋。
- 分枝型：側身呈現較多分叉。
- 尾脈型：尾部有較長的紋路延伸。
- 碎脈型：局部呈短小間斷紋路。
- 異色型：顏色不同，但不預先賦予特殊能力。

**生成測試原則**：同一物種共享基本骨架／輪廓，紋路使用可重現種子；不要將外觀差異直接當作遺傳學證據，真正的遺傳與表現型規則待生物設計階段確定。

## 四、飼養箱開發原型

開發時先用**不對正式玩家開放的測試個體**：

1. 建立測試物種 ID、個體 ID、固定 `patternSeed` 和暫定外型變數。
2. 放入隔離測試飼養箱，檢查渲染、縮放、觀察與互動。
3. 驗證相同個體反覆載入，紋路與 ID 不會無故改變。
4. 後續加入行為、食性、環境與健康需求前，先完成可信的生態設定；避免用幻想數據冒充現實飼養知識。
5. 只用於測試，不將傳說個體預先發放給新手，也不提前串接正式玩家存檔／交易。

## 五、傳說事件開發原型

沿用 `docs/LEGENDARY_CREATURE_TIME_EVENTS_C.md` 的 **C 混合制度**：

- 個人世界：以固定事件 ID、世界種子、研究線索與環境條件形成個人化遭遇窗口。
- 世界級：少量共同窗口，伺服器確認真實時間、捕捉資格與唯一性。
- 觀察、研究、捕捉、取得飼養權四個階段分離；正式保育與合法性設計未完成前，不先宣稱一定能抓或養。
- 修改裝置時間不能自行解鎖稀有捕捉或獎勵；未連線只能保留適當的觀察／研究草稿。
- 若錯過時間，未來應有符合生態與世界觀的再次遭遇機會，不以玩家現實作息懲罰玩家。
