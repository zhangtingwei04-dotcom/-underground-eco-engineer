# Cloudflare 存檔還原（2026-11-08）

## 已部署
- Worker `scales-seeds-save-api` 新增受驗證保護的 `POST /v1/restore`。
- 請求格式：`{ "targetRevision": 1, "expectedRevision": 2 }`。
- 由 Supabase Auth 確認登入使用者，所有 D1 存取均限制於該使用者的 `save_id`、`player_id`。
- 還原**不刪除歷史**，將指定歷史內容寫成下一版，例如從 2 還原至 1 產生版本 3。
- 使用 `expectedRevision` 阻止舊裝置直接蓋過新版本；版本不符合返回 `409 revision_conflict`。
- 既有存檔寫入時，自動在 `save_revisions` 留下版本快照。這是「每次成功寫入的版本紀錄」，**不是**獨立地區的災難備份，也不是定時備份。
- `src/systems/cloudflare-save-client.js` 新增 `restore(targetRevision, expectedRevision)`。
- `cloud-save-test.html` 新增兩個限定 `_testOnly` 的按鈕：「建立版本 2」和「還原版本 1」，還原前再確認使用者同意。
- 部署已在 Cloudflare 管理 API 確認，但新的還原請求**尚待在瀏覽器以測試帳號執行端對端驗證**。

## 測試計畫
1. 測試帳號登入後點「唯讀測試」；目前測試存檔應為版本 1。
2. 點「測試專用：建立第二版存檔」，確認後應建立版本 2。
3. 再點唯讀，確認版本 2 才能按還原。
4. 點「測試專用：還原版本 1」，確認後應取得版本 3，內容標記恢復為 v1。
5. 點「檢查自己的歷史版本」，預期至少 3 筆。
6. 如 API 回傳 409、503、或驗證失敗，暫停並檢查，不重複點擊寫入。
