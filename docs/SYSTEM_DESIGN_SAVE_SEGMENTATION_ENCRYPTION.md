# 《鱗片與種子：地下生態物語》存檔分流、加密及可信資料架構

**決策日期：2026-11-08**  
**狀態：設計方向已確認／實作分階段進行**  
**適用：網頁、未來桌面與手機版、Ohm Core**

## 一、核心決策
1. **採邏輯分流，不急著拆資料庫**：先統一存檔規格與每個模組的資料所有權，後續依規模決定是否拆表、拆檔、分區同步。
2. **加密分階段導入**：傳輸採 HTTPS，雲端儲存的加密能力與權限配置需核實；個人匯出備份可提供經過驗證的可選密碼加密機制。加密並不能單獨防作弊。
3. **伺服器可信資料分離**：遊戲經濟、交易、獎勵、排行榜與涉及玩家互動的稀有資產，未來應以伺服器交易紀錄和遊戲規則作權威來源；從本機匯入的數值不得自動取得可信資格。
4. **可還原、可遷移、不可靜默覆蓋**：必須有 schemaVersion、世界 ID、存檔槽 ID、修訂版本與備份流程；遇到衝突、未知格式或讀取失敗先停止，不自動重置或覆蓋。
5. **繼續維持免費優先**：現階段建立小型、可測試的模組，不增購付費服務，也不讓安全工程延誤核心遊戲玩法。

## 二、邏輯資料區塊（規劃）
| 區塊 | 主要資料 | 信任等級及規則 |
|---|---|---|
| AccountMetadata | 帳號綁定、世界及槽識別、修訂版 | 身分來源須由後端確認，不信任前端宣稱的玩家 ID |
| WorldState | 地圖、時間、探索、場景狀態 | 可本機暫存，跨裝置必須做版本比對與離線重複結算防護 |
| LivingEntities | 寵物、環境、NPC 關係及個體生命史 | 個體採穩定 ID，避免不同裝置或版本遺失紀錄 |
| ResearchJournal | 研究成果、圖鑑、日誌、觀察 | 區分玩家私人記錄和伺服器認證的研究獎勵 |
| DevicePreferences | 語言、音量、觸控等偏好 | 以裝置資料為主，不能無意覆蓋其他裝置設定 |
| TrustedLedger | 可交易資產、交易、可信獎勵和排行榜 | 未來由伺服器權威管理；匯入 JSON 不得直接增發 |

這些是**邏輯區塊**，不等於目前已存在上述資料庫表格或分檔。初期仍可使用單一版本化存檔封裝承載多個區塊。

## 三、建議封裝格式（僅為設計示例）
```json
{
  "format": "scales-seeds-save",
  "schemaVersion": 1,
  "worldId": "stable-world-id",
  "slotId": "main",
  "baseRevision": 0,
  "sections": {
    "world": {},
    "livingEntities": {},
    "researchJournal": {}
  },
  "integrity": {
    "algorithm": "SHA-256",
    "digest": "calculated-at-export"
  }
}
```
- SHA-256 只能協助偵測意外毀損；若攻擊者能修改資料並重算雜湊，**不能防作弊或證明存檔為官方核准**。
- 認證的來源與版本紀錄需由後端驗證。若需證明伺服器產生過某份資料，可考慮伺服器私鑰簽章或帶密鑰的 MAC，秘密金鑰不得存在前端。
- 匯入前檢查檔案大小、型別、schemaVersion、ID、資料內容及是否有衝突；先建立安全備份，玩家明確確認後才執行。
- 不在匯出檔中加入 Supabase access token、refresh token、密碼、API 私密金鑰等。
- 未知 schema 不得偷偷降版、覆蓋或產生新世界。

## 四、加密方案
- **傳輸中**：使用 HTTPS/TLS。
- **服務端儲存**：確認 Cloudflare D1、Supabase 的實際靜態加密與備份措施及帳號權限；不可把前端加密當成存取控制。
- **本機瀏覽器**：優先可恢復與可靠儲存，必要時再評估資料加密；瀏覽器腳本可存取的解密金鑰無法提供完整防篡改保障。
- **玩家匯出檔案**：未來可選擇使用 Web Crypto 等成熟加密方案，經 KDF（例如具適當參數的 PBKDF2／Argon2）由使用者密碼衍生金鑰，搭配 AES-GCM 及隨機 salt/nonce；記錄加密格式與版本。不要自創加密演算法。
- **金鑰遺失處理**：加密匯出必須說明密碼遺失可能無法還原，不得保證服務方一定能解密；必要時提供不加密的本機備份選項並清楚提醒風險。

- 已有舊 SaveSystem／Supabase 雲端保存、Cloudflare D1 測試版存檔與歷史修訂、獨立離線待同步模組。
- 尚無完整檔案匯入／匯出流程、正式自動同步、可信資產總帳或玩家密碼加密匯出。

- 未經遷移與備份驗證，不直接修改正式玩家存檔流程。

## 七、與獨立核心的關係
Ohm Core 不直接依賴 Phaser、IndexedDB、Supabase 或 Cloudflare；資料模型／驗證／遷移邏輯保持可獨立測試。網頁、桌面與手機的儲存、加密、檔案選擇與雲端存取均由平台適配器負責。
