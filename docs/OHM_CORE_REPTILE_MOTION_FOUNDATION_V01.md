# Ohm Core — 真實爬蟲動態與習性系統基礎 v0.1

日期：2026-11-08
狀態：**最小規則模組已提交；非完整動畫、物理、習性 AI 或正式生態模擬**

## 已確定的開發優先順序
1. 優先研究與製作多種**真實爬蟲**的運動方式和自然行為，從可靠物種資料建立獨立檔案。
2. 以可共用的核心介面描述動作能力、合法狀態轉移、個體狀態；**不假設所有爬蟲都會攀爬／游泳／挖掘**。
3. 動畫、美術、骨架、行走路徑、碰撞等交由 Phaser 或將來的 Ohm Renderer 適配器，Ohm Core 不持有 Phaser 物件。
4. 多種真實物種經生物學、動態、效能及行為驗證後，才開始虛構傳說級生物（第一個保留候選：晶脈夜蜥）。
5. 暫不改動正式遊戲存檔，不添加虛構生物；遵守免費優先、模組化與既有功能相容。

## 本次已建立
- `src/ohm-core/reptile-motion.mjs`
  - `MOTION_MODES`：基本動作模式的技術詞彙（休息、步行、滑行、攀爬、掘洞、游泳）。
  - `BEHAVIOR_TAGS`：行為分類的技術詞彙（休息、探索、覓食、進食、躲避、曬背）。
  - `validateMotionProfile(profile)`：檢查物種 ID、能力清單、狀態轉換、無重複值及資料審查狀態。
  - `createMotionState(profile,{individualId,mode})`：建立個體的獨立運動狀態。
  - `requestMotion(state,nextMode,profile)`：只允許物種清單中的狀態轉移；產生事件、不修改原狀態。
  - `DEMO_MOTION_PROFILE`：純機械測試資料，**不是任何真實物種的生態資料**。
- `tests/reptile-motion.test.mjs`：物種配置檢查、狀態轉換、拒絕不支援模式及純函式狀態更新的單元測試。
- `.github/workflows/ohm-core.yml`：加入 Node.js 單元測試指令。

## 模組責任邊界

```text
真實物種資料、文獻與研究結果
             ↓
Ohm Core: 物種動作能力／個體狀態／行為規則（純資料與純函式）
             ↓ 發送 motion_changed 等事件
平台 Adapter: 動畫資源／骨架／位置／音效／輸入
             ↓
Phaser（目前）或未來自有 Renderer
```

**行為類別不等於已實作的生態行為決策。** 目前的狀態切換是測試性指令，並未模擬蛇類側向波動運動、守宮附著、個體應激反應、睡眠節律、攝食、體溫調節或真實運動物理。這些未來應按不同物種分開研究。

## 未來增量
- 建立具有來源、日期、審查狀態的真實物種設定；對尚無證據的習性採未確認欄位，不自行填入。
- 動作狀態補上速度、姿態、動作優先級、能量與地形能力，但不搶先決定跨物種共用數值。
- 建立生態箱環境條件接口，再用環境和個體狀態選擇可行行為；避免將所有生物擬人化。
- 在獨立 demo 測試 Phaser adapter、跨平台動畫事件與效能，再評估接管正式生態箱。
- 紋路／遺傳與運動模組分離，待真實物種資料完善後再整合。

## 驗收狀態
原始碼與 GitHub Actions 工作流程已提交，**但 GitHub Actions 的實際執行結果、真實瀏覽器或手機端整合尚未經本次確認**，不能宣稱遊戲已具完整爬蟲運動／習性功能。
