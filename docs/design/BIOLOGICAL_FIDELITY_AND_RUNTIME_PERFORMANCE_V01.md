# 真實生物資料庫與遊戲執行效能分離原則 v0.1

日期：2026-11-08
狀態：已確認的開發方向；屬設計決策文件，並非已實作功能。

## 核心決策
《鱗片與種子：地下生態物語》優先蒐集、保存並核對高真實度生物研究資料；**不因當前手機或 Phaser 效能限制而刪減科學研究本體**。之後根據實測流暢度，決定遊戲執行版本要保留哪些精細運算、採取哪些近似或預先計算動畫。資料本體、研究模型、正式執行版本須清楚分離。

## 三層架構
1. **研究／生物資料庫（Evidence & Species Database）**：保留原始研究來源、DOI、版本、研究物種、單位、實驗條件、數據品質、授權、適用範圍和不確定性。大檔原始影片與第三方 ZIP 應放在獨立、授權合規的研究儲存區，GitHub 主要存索引與驗收紀錄；此層不等同於實時遊戲存取。
2. **真實度參考模型（Reference Simulation / Model）**：按研究證據建立可能的生理、行為與運動模型；允許較高精度與離線運算。要明確標示「直接研究支持」「推估」與「遊戲創作」，避免把一種蛇的實驗數據套用到所有物種。
3. **遊戲執行模型（Runtime Presentation / Model）**：依手機與電腦的實測效能，將高精度模型轉換成可維護的骨架動畫、曲線、行為狀態機、事件及分區生態更新，不強制在每個影格跑完整物理模擬。

## 流暢度驗證原則
- 先建立可靠的對照範例，再以實際設備量測幀時間（frame time）、幀率、記憶體、耗電／發熱與可同時活動的生物數量。
- 測試場景包括單一蛇類近距離觀察、同屏多隻生物、不同裝置、前後景及長時間運行。
- 提供可逐級切換的運算詳細度，**精簡動畫不等於竄改物種的生態事實**；未顯示場景可用事件或時間摘要更新狀態。
- 沒有性能測試前不武斷規定某種骨架節點或 fps 一定可行；依可量測指標而非臆測選方案。
- 保留必要的行為一致性與存檔連續性，避免不同品質設定改變動物健康或研究成果。

## 近期工作順序
1. 依使用者希望**先大量蒐集研究數據**：優先驗收來源、原始檔、單位、授權及物種適用性。
2. 建立統一研究索引（manifest），區分實測軌跡、統計摘要、實驗影片、研究程式和物種生態文字。
3. 累積足夠代表性後建立高真實度模型及比較用示範，再實際測試效能並選擇遊戲表現方案。
4. 在正式決定之前，不擅自削弱研究資料內容或直接重寫既有遊戲動畫。

## 版權與技術獨立性
- 原始研究資料使用須遵守各來源授權；不等於所有資料都可公開打包進商業遊戲。
- 研究資料格式、參考模型與遊戲執行模型解耦，供未來 Phaser 以外的跨平台運行核心使用。
