# 《鱗片與種子：地下生態物語》傳說生物時間與捕捉事件設計 — C 混合制度

日期：2026-11-08
狀態：**使用者確認的方向／規格設計，尚未正式實作**
歸屬：生態探索、研究等級、事件排程、伺服器驗證、個人世界生成

## 1. 決策與核心理念

採用 **C：混合制度**。
- 少數「世界級傳說事件」全玩家共享同一個開放時間與條件。
- 多數「個人世界傳說事件」依每位玩家的世界 ID、世界生成種子、研究進度與環境條件生成，各玩家的時間與線索可以不同。
- **真實的季節性／特定時段物種**仍依可考證的物種生態設定，不能因傳說事件機制將真實物種描述成虛構神話。
- 虛構的傳說物種應與真實物種圖鑑明確分隔，預計在玩家具備生態研究基礎、後期特殊棲息地開放後才逐步登場。
- **觀察、研究認證、取得／飼養**是不同進度；找到不等於可捕捉，符合時間也不等於保證取得。

## 2. 事件類別

### A. 世界級傳說事件（少量、同步）
- 例如歐姆地下特殊生態週期、區域性共通傳說事件。
- 全體玩家共享**伺服器認定**的事件窗口（eventId、startAt、endAt、version）。
- 同一事件可有不同個人線索／地點／難度，但全球窗口一致。
- 機制不得採客戶端 Date.now() 作為傳說生物捕捉或稀有獎勵的唯一依據。
- 未登入、沒有網路的玩家可先查看已緩存的資訊，但高價值捕捉與可交易資產應等伺服器確認。

### B. 個人世界傳說事件（主要形式）
- 使用伺服器保存的 worldId、不可隨意重抽的事件種子及研究資格，計算個人事件條件。
- 生成後把事件 ID、窗口、生成版本、完成狀態持久化；不能透過重新開遊戲、清空快取、跨裝置登入無限重抽。
- 允許個別世界有不同季節、棲地線索、時段與探索前置任務，但正式觸發和可交易成果仍需伺服器驗證。
- 以**可再生窗口／循環條件**優先，不設計成錯過一次便永久無法取得。

### C. 真實物種季節／時段探索（與傳說系統分離）
- 時間、季節、環境因子應依物種、地區與文獻設定，日行、夜行、晨昏活動不能概括所有同類物種。
- 季節及時段影響**遭遇或行為觀察機率**，而不是無條件直接給予捕捉權利。
- 保育、合法捕捉限制與飼養設備前置條件維持既有世界觀規則。

## 3. 可擴充事件資料模型（設計示意）

```json
{
  "eventId": "example-legend-001",
  "scope": "worldwide",
  "speciesId": "fictional-species-id",
  "schemaVersion": 1,
  "window": { "startAtUtc": "TBD", "endAtUtc": "TBD" },
  "requirements": {
    "researchTier": "TBD",
    "habitatId": "TBD",
    "permitId": "TBD",
    "environmentConditions": []
  },
  "encounter": { "eligible": false, "guaranteedCapture": false },
  "policy": { "repeatableWindow": true, "offlineParticipation": "protected_reentry" }
}
```

上方僅示意欄位；非正式物種、活動時間或稀有度定稿。正式結構應另外拆出：公開事件配置、每玩家資格、每世界生成結果、觀察紀錄、捕捉與獎勵稽核。

## 4. 玩家錯過事件時

- 不要求玩家為了稀有生物熬夜、在工作時登入或修改手機時間。
- **普通季節性生物**：下次合理的季節／棲地條件仍可探索，必要時提供研究線索與其他自然棲地。
- **個人世界傳說**：可用研究進度與線索安排再次出現機會，不保證每次都取得；重排必須由規則確認，不能靠修改日期。
- **世界級傳說**：提供合理活動期間，研究紀錄／圖鑑可以保留；對錯過期間的玩家，考慮後續重演、替代調查或可重開的非競爭內容。不要強迫每日登入。
- **觀察／回憶**不自動等同於**捕捉／可交易獎勵**。錄像、研究回顧不可重複領取同一獎勵。
- 避免「現實中錯過一次就永遠失去主線或關鍵研究認證」；稀有感來自探索與準備，不只靠玩家現實作息。

## 5. 防止修改裝置日期、離線回溯作弊

1. 四個時間檢查點（00:00、06:00、12:00、18:00）僅管理**低頻世界狀態**；並不代替傳說事件的精確窗口。
2. 時間窗口需要精確 UTC 時間戳與確定時區顯示；裝置時間只能影響 UI 預覽，不能核准傳說生物捕捉。
3. 伺服器以可信時鐘驗證：事件仍開啟、世界與帳號身份、研究資格、所在地、捕捉資格、事件版本、是否已完成／領取。
4. 捕捉與獎勵採**伺服器權威、唯一事件憑證與冪等處理**，以防時間跳轉、重播請求、多裝置重複捕捉。
5. 離線時允許非交易性的觀察／準備行為；需驗證的稀有個體與獎勵保持待確認，不能根據客戶端修改的時鐘提前創造可信資產。
6. 發現時間異常時保留玩家進度，提示需要連線校驗，不應直接封號或清除存檔。
7. 長時間離線的四時段摘要**不能反推**玩家確實在某個限定窗口親自完成捕捉。

## 6. 與遊戲核心的整合順序

**前期（現在）**
- 記錄 C 混合制度與邊界，不增加新的付費雲服務。
- 傳說系統先採規則與資料結構設計，不動正式存檔、NPC、捕捉或 Cloudflare API。
- 日常真實物種研究、第一人稱 2D 場景與一般野外探索優先。

**中期**
- 建立獨立的事件條件評估器、可重現且不可由玩家任意重抽的個人世界事件生成、研究資格檢查。
- 事件 UI 提供線索、適當時間、預約調查或回顧方式，避免日常登入義務。
- 做好跨裝置與離線狀態，不允許過期進度靜默覆蓋。

**後期／對外測試前**
- 伺服器權威世界級排程、個人世界生成記錄、捕捉及稀有獎勵核准。
- 原子化去重、防重播、跨裝置、改時鐘、修改存檔的驗證。
- 依保育規則區分允許觀察／研究／捕獲／飼養的物種；測試不同作息玩家能否合理參與。

## 7. 暫未定稿
- 世界級傳說事件占比、每年次數與每次開放天數。
- 個人傳說事件的保底與再次出現政策。
- 各種傳說物種、確切分布、捕捉方式、許可證名稱及研究門檻。
- 地下國家的專屬季節與時區如何對應現實。
- 是否允許特定傳說物種交易；在安全機制確立前不承諾。
