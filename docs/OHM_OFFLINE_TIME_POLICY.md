# Ohm Core — 離線時間與四時段補算基礎（2026-11-08）

## 決策
玩家不在線時，網頁遊戲**不在背景持續模擬**。回到遊戲時，取「上次可信時間」與「目前時間」計算離線區間，使用**一次性摘要結算**，不逐分鐘重播 NPC 行程。世界時間不因切換場景或操作增加。

## 適用情境
- **網路斷線但遊戲仍開啟**：本機可繼續只讀時間和不需要網路的功能；要同步的資料等恢復連線再處理。網路斷線不代表時鐘停止。
- **遊戲切到手機背景**：瀏覽器計時器可能暫停；回到前景重新校準，判斷是否跨越凌晨 00:00、早上 06:00、中午 12:00、晚上 18:00 的檢查點。
- **完全關閉遊戲、數天後重開**：未來由存檔中的 `lastProcessedAt` 和目前時間規劃一次性摘要，不補播每個 NPC 在離線期間的所有事件；本階段不更動正式存檔。

## 已新增的純計算模組
- `src/ohm-core/offline-catch-up.mjs`：`planOfflineCatchUp({lastSeenMs,nowMs,maxDays,offsetMinutes})`，用時間戳計算離線總長、摘要計算區間、跨過四個檢查點的次數。
- 預設最多計算 30 天，超出標示 `capped:true`，避免離線多年時造成巨量運算；**30 天是暫訂技術保護上限，不代表寵物只能保留 30 天或超出即受罰**。
- 使用 +08:00 時區固定偏移作為目前台灣時區原型。正式跨時區／日光節約時間地區需改為時區感知適配器。
- 此模組**不修改任何資料、不發獎勵、不補寫 NPC 行程**，只回傳資訊；另有 `tests/offline-catch-up.test.mjs` 和 GitHub CI 設定。
- 現有 `DailyTimeNotifier` 仍只用於**遊戲開啟期間**的四次通知；此離線摘要尚未串接存檔或正式 NPC／寵物系統。

## 未來正式結算規則（規劃，未實作）
1. 讀取上一次**已成功結算且已持久化**的時間，而非僅以最後登入時間當進度依據；不可只更新時間卻沒成功寫入資料。
2. 校驗 `now >= lastProcessedAt`、世界／帳號身份、版本與裝置時鐘異常。重要資產與獎勵需由後端可信時間判斷。
3. 用時間區段結算**合理的環境變化**，但寵物健康與死亡等重要結果另設保護及物種規則，避免玩家離線遭遇不公平的不可逆損失。
4. NPC 按個性、工作及日程決定**當前狀態**；離線期間沒實際發生的約會、感情互動或重大事件不得憑空生成。
5. 同一次離線區間採唯一結算 ID、原子提交及版本檢查；避免重新登入、不同裝置同步時重複發放獎勵。
6. 玩家返回時可選擇顯示簡短「離線期間世界摘要」，不要顯示冗長流水帳；不強迫玩家每日登入。
7. 完整存檔整合、同步衝突、時間防作弊與備份仍安排在專案中後期。

## 實作與驗收界線
目前已建立**純邏輯計算與測試程式**，但未完成正式遊戲離線結算。本文件不可被理解為玩家已能離線成長、跨裝置自動結算或在離線期間取得獎勵。


## 防止離線修改裝置時間（2026-11-08 補充）

### 威脅模型
- 玩家可能將裝置日期快轉或倒轉，製造虛假的離線天數，試圖取得寵物成長、研究獎勵、商店重置或可交易資產。
- `Date.now()`、瀏覽器 `performance.now()`、localStorage/IndexedDB 和玩家持有的檔案都不是跨關閉、跨裝置的可信權威。單調時鐘只適合在**同一個執行階段**偵測突然跳時，不能保證關機後的實際離線秒數。
- 即使有本機 SHA-256 或本機加密，也不能防止可控制裝置的玩家篡改存檔或重新計算校驗碼。

### 信任分級
1. **純展示／本機休閒**：可使用裝置時間，異常時顯示時間需要確認，不刪檔不封號。
2. **單人離線進度**：採保守上限、版本與重複結算保護；缺乏可信時間時可暫緩不可逆結果，允許玩家繼續遊玩。
3. **可兌換獎勵、交易、排名等**：僅由後端可信時間與已提交的事件／交易紀錄決定；不得單憑客戶端宣稱離線天數發放資產。

### 未來建議協定（設計，尚未接入）
- 上線時向伺服器取得與玩家帳號綁定的時間錨點（如 `serverSeenAt`、`lastSettledAt`、修訂版本），重要計算由伺服器自行取得時間，不信任客戶端上傳的現在時間。
- 離線期間只紀錄待驗證的進度意圖；登入後先取得後端現在時間，再以 `lastSettledAt` 計算合法可結算區間。
- 後端應在一個原子交易中執行「檢查版本／上次結算點 → 發放一次獎勵 → 更新結算點與修訂版」，使用冪等結算 ID 防止重複請求。
- 時鐘倒退、大幅跳躍、跨裝置衝突時，標記為 `verification_required`，保留所有玩家資料，不依異常直接判定作弊、扣除資產或重置。
- 手機長期無網路時，讓不影響公平性的內容繼續玩；涉及交易和可兌換獎勵則待恢復連線確認，並清楚告知玩家。
- 不因時區切換直接認為作弊：存 UTC 時間戳，畫面按指定時區呈現。固定四時段排程與經過的真實時間須分開。
- 不把 30 天技術補算上限當成防作弊的唯一規則；超過上限應用摘要、分段計算或人工可理解的寬限策略，不應默默吞掉玩家合法權益。

### 實作狀態
此節僅是風險處理規範。**現有雲端存檔 API 尚未提供權威時間錨點或可信獎勵結算，純離線計算模組不能保證阻止改時鐘作弊。** 中後期整合前必須補上後端驗證、安全測試與跨裝置驗收。
