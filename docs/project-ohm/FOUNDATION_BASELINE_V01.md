# 歐姆計劃｜工程基礎與採納守則 V0.1

**建立日期：**2026-11-10  
**適用對象：**《鱗片與種子：地下生態物語》及逐步成形的 Project OHM  
**狀態：**本文件是基礎管理規範及部分已實作的測試工具，不代表完成一套可取代 Phaser 的遊戲引擎。

## 2. 資料分層，不把所有研究塞進遊戲

**Archive 原始研究與索引 → 已核實精簡資料 → Core 獨立算法／規則 → 渲染與平台 adapter → 遊戲。**

- 大型論文、CSV、影片、3D 模型與第三方原始專案存外部原始來源或授權合適的研究儲存空間；GitHub 只保存可公開的自寫摘要／索引／合法必要素材。
- 研究資料要有來源、取得日期、授權、可用範圍、證據限制、版本與處理狀態。科學結論、遊戲平衡、虛構世界觀分開。
- 正式遊戲只載入場景需要的數據和程式。離線模擬可用低頻結算，不能讓全部世界和 NPC 每秒無差別運作。
- 目前使用已有的 `docs/research/` 與生物研究 D1 索引，**不再建立第二個重複 D1**，研究資料庫與玩家存檔仍分離。

## 3. 模組的最低合約

新模組至少具有：

1. 唯一 ID、責任說明、程式入口、文件路徑、目前階段、測試路徑及正式整合證據。
2. 清楚、穩定的輸入／輸出；對外回傳可辨認的錯誤，不依賴神秘全域變數。
3. Core 優先採純 JS 規則，不在 Core import Phaser、window、DOM、localStorage、Supabase 或 Cloudflare SDK。
4. 與事件、資料模型及存檔版本分離；如變更世界狀態結構，須制定向前／向後相容與遷移策略。
5. 第三方引用標明授權與 COPYRIGHT／NOTICE 條件；不直接把授權不明模型或美術搬入正式遊戲。
6. 先獨立 demo，再單元／整合／手機驗證，最後透過 adapter 受控進正式遊戲；記錄回退方案。

**目前的機器可讀登錄**在 `src/ohm-core/module-catalog.mjs`：只顯示保守狀態。`prototype` 代表已有程式入口，但**不等於已通過正式測試**。`tested` 必須有對應測試；`integrated` 還需要明確整合證據。登錄器不能自動證明 CI 成功或手機實測完成；每次提升狀態都需人工核對證據。


未來若需真正的引擎場景或多個實驗，可以再新增 `src/ohm-engine/` 或 `labs/`；**現在不建立空資料夾、重複架構或未使用的框架**。

## 5. 品質與安全底線

- **向下相容優先**：不修改主遊戲登入、存檔、RLS、Cloudflare 資料庫及正式 UI；需更改前另列風險與還原方式。
- **隔離實驗**：Lab 不載入真實玩家存檔或真實帳號 token；用合成演示資料。原始生態素材經過授權檢查，涉及玩家的資料須最小化保存。
- **公開 Repo 風險**：本 repo 目前是 public，所有新推送的原始碼／研究規格可以被第三方看到；未公開原創素材、內部筆記與商業秘密應另存私有地方，不在此複製。**此輪沒有新增 LICENSE，也沒有替使用者決定全面開源。**
- **費用控制**：免費優先，未建立新訂閱、新付費外掛或額外 D1 資料庫；有必要時再評估每月支出與免費額度。
- **可回溯**：GitHub main commit 是文件與技術版本來源；推動每項模組整合前建立測試、示範、失敗情境及可恢復策略。
- **正式發行**仍須測試 iPhone 與桌面載入、幀率、記憶體、網路斷線、跨裝置存檔一致性、安全、授權與玩家隱私。
