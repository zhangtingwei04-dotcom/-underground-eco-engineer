# 歐姆計劃｜PROJECT OHM

> 專案建立：2026-11-10｜版本：V0.1（計畫與資料整合架構）
>
> **目標：一邊製作《鱗片與種子：地下生態物語》，一邊累積可信研究資料、驗證技術、逐步建立能長期使用和替換的自有遊戲引擎。**
>
> **狀態聲明：**「歐姆計劃」是長期技術計劃的正式名稱，不代表已完成一套獨立渲染、物理或跨平台遊戲引擎。

## 1. 正式定位

**歐姆計劃（Project OHM）** 是技術研究、軟體架構和遊戲引擎自主化的總計劃。第一款實際應用與驗證它的作品是《鱗片與種子：地下生態物語》（Scales & Seeds）。

三個工作分區（英文子名稱可於未來調整，不另立重複系統）：

1. **Ohm Archive｜歐姆研究資料庫**：蒐集、核對、分類、索引公開研究、真實影音、數據集、工程參考與授權資訊；將科學事實和遊戲設定明確分離。
2. **Ohm Core｜歐姆遊戲核心**：與引擎平台無關的遊戲狀態、規則、模擬、時間、生物動態、NPC、場景資料、存檔 schema；目前已在 `src/ohm-core/` 有初步獨立模組。
3. **Ohm Engine｜歐姆自研引擎**：未來由我們逐步建立／替換的動畫、攝影機、場景、渲染、物件管理、編輯工具與跨平台適配能力；目前仍是長期目標，**不是完成品**。

**依賴方向：**研究資料經人工與測試核對後才成為可載入的遊戲資料／可重用演算法；遊戲核心不依賴 Phaser、DOM、瀏覽器儲存或雲端 SDK；Phaser 目前仍負責遊戲呈現；未來自研引擎透過公開接口逐項替代。

```text
  研究、論文、影音、工程與開源工具
                ↓ 核對、授權、證據限制
       Ohm Archive（來源索引）
                ↓ 經驗證的精簡資料／規則
       Ohm Core（無平台依賴）
                ↓ 指令、事件、狀態／介面
   Phaser（現有） ⇄ Ohm Engine（逐步接手）
                ↓
  《鱗片與種子》 Web → 桌面／手機
```

## 3. 「大量資料」如何累積，卻不拖慢遊戲

- **研究原始資料**：公開論文、來源網址、研究資料集、合法影片、工程文件。能合法取得的放在合適的研究儲存區；不能明確授權重用或太大的原始資料只保存來源與筆記。不直接打包到正式遊戲。
- **索引與證據層**：小型中繼資料、關鍵字、物種／動作／模組關聯、來源品質、授權、證據限制；GitHub Markdown 作為可追溯紀錄；現有 D1 可支援生物科學查詢，不把玩家存檔與研究索引混用。
- **可用遊戲資料**：從研究提煉出帶版本、可驗證、經過遊戲平衡處理的 JSON／設定／數值／行為參數；只按場景／物種需求載入，避免整庫進遊戲。
- **引擎程式碼**：原創、可測試、清楚輸入輸出的規則與工具。第三方程式若真的移植，保存相應許可與著作權通知；不得假裝是完全原創。
- **世界觀資料**：歐姆虛構物種、生物、晶礦和地理與真實科學研究分開標示。不可讓玩家誤以為虛構研究是現實證據。

## 4. 收集 → 整理 → 驗證 → 加入的採納流程

每一個資料或模組至少經過：

1. **FOUND｜找到**：記錄標題、作者、來源網址、取得日期、用途與所在目錄；此時僅代表發現。
2. **CHECKED｜已核對**：確認來源與可存取性，標記已取得全文、節錄、只有摘要或尚未核實。
3. **LICENSED｜可合法使用**：查核資料集、模型、圖片、音樂、程式碼等不同權利；無重用授權時只做閱讀與獨立研究。
4. **PROTOTYPE｜獨立試作**：先在隔離的 demo 製作，不改正式世界、不動真實存檔。
5. **TESTED｜測試通過**：用可重複的測試確認正確性、效能、兼容性與必要回復方式。
6. **INTEGRATED｜受控整合**：由 adapter 或受控介面接入主遊戲，完成玩家可見的實際驗證。
7. **MAINTAINED｜正式維護**：記錄版本、變更、來源與相容性。新研究可再次修訂，舊版本可追溯。

不要求每份公開資料都完整走到 INTEGRATED；研究價值和遊戲採用價值是兩回事。

## 5. 優先資料領域（可持續擴展）

| 類別 | 研究資料例子 | 初步可做出的模組 |
| --- | --- | --- |
| 生物與生態 | 物種、行為、解剖、環境、動態、論文與影片 | 物種知識、觀察、行為、離線生態模擬 |
| 物理與交通 | 曲線運動、視差、懸吊索道、車廂連接 | 路徑、攝影機、纜車動畫、避碰 |
| NPC 與社會 | 時間排程、事件、情緒與關係設計 | 生活作息、事件選擇、對話與記憶 |
| 美術與音樂 | 視覺參考、原創素材、授權資料、聲景 | 渲染、音效調度、UI、場景資源 |
| 世界與地質 | 土壤、水文、岩石、洞穴、植物、地形 | 環境資料、地圖生成、探索 |
| 平台與安全 | Web、App、PC、同步、版本遷移 | 輸入、效能、備份、權限及跨裝置服務 |

新增領域先建立來源索引，不因資料量而強迫增加即時模擬、每日任務或不必要的程式負擔。

## 6. 不可違背的底線

1. **慢生活原則**：深入的生態與 NPC 不應增加玩家行政負擔，不因離線造成強制回訪壓力。
2. **可更換、可回退**：每次僅逐項從 Phaser 提取/替換成熟功能；不先重寫全部、不破壞既有玩家存檔。
3. **跨平台**：核心算法與資料模型和平台隔離；Web 為現有首要平台，桌面／手機按成熟度跟進。
4. **性能**：資料按需載入；大檔不嵌入主遊戲；對行動裝置進行記憶體、幀率和耗電測試。
5. **安全**：GitHub repo 目前為 **public**。這裡只保存適合公開的規格、連結與程式；不提交金鑰、非公開原創資產、玩家存檔、未授權作品或任何私人資料。未公開的原創美術／敏感資產另評估私人儲存。
6. **版權**：免費閱讀和免費下載不等於可再利用；記錄來源、作者、授權、署名與商業使用條件。
7. **成本**：現階段免費優先，不因「建立自研引擎」而自動啟用付費運算、外掛或雲端服務。
8. **誠實標示**：研究過 ≠ 測試過；已有程式 ≠ 已整合；有實驗畫面 ≠ 引擎完成。

## 7. 第一批小里程碑

**M0｜本次：建立歐姆計劃入口與資料索引**（文件已建；不代表程式完成）
- 確認正式名稱、現有基礎、研究分類、授權與採納流程。
- 對應模組和已存在研究，避免重新蒐集同一資料。

**M1｜第一次獨立運動試作**
- 根據 `docs/research/transport/CABLE_TRAIN_MOTION_RESEARCH_INDEX_V01.md` 做 S02-B v09 3 秒路徑測試。
- 車廂持續前進、順彎道排列、與懸吊結構保持連續，並有可信的車窗視差。
- 在隔離測試頁進行，不修改正式登入、存檔或已核准的原創美術。

**M2｜研究與模組的查詢／驗證**
- 優先補齊研究資料的來源、證據分級、授權與可重用性；建立可搜尋的索引（不強求一次做完整網站）。
- 在跨平台核心中只加入確定有用、能獨立測試的規則；先由 Phaser adapter 試用。

**M3｜逐項替換與長期累積**
- 將交通路徑模組、蛇類動態等已通過性能測試的功能作為 Ohm Engine 候選。
- 渲染器、物理系統、可視化編輯器都延後到有成熟使用需求再實作。
